## QA-04 — High — plaintext credentials are accepted and stored as references

`DeviceRegistrationRequest.CredentialReference` is an unconstrained caller-supplied string. `InMemoryDeviceRepository.CreateAsync` copies it directly into `Device.CredentialReference`; neither layer validates that it is a reference rather than credential material.

The acceptance probe submits `synthetic-plaintext-password`. The repository accepts, stores, and returns that exact string. The implementation therefore relies on callers obeying the property name and documentation. AC02 requires credentials to be referenced, not stored in plaintext; a naming convention is not an enforceable boundary.

### Reproduction

```sh
dotnet run --project evidence/BIO-DEV-001/acceptance/PlaintextCredentialProbe/PlaintextCredentialProbe.csproj
```

Current result: `FAIL plaintext credential accepted, stored and returned unchanged`, exit `1`.

Required closure: replace the raw string with a validated credential-reference value object or enforce a strict supported-reference grammar at request and repository boundaries. Reject ordinary plaintext, credential-bearing URLs, empty/whitespace values, control characters, and unsupported schemes. Add service and composed-host negative tests proving plaintext never enters or leaves a stored device record.
