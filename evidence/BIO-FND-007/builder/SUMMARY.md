## CHANGES_REQUIRED round 1 — BIO-FND-007-QA-01 (fixed)

Seyi's independent review (`evidence/BIO-FND-007/codex/REVIEW.md`, commit `47f5dc4`) found one
real defect, now fixed in this commit:

- **QA-01 (Medium):** the closed mobile nav drawer was moved off screen only with
  `transform: translateX(-100%)`. It stayed rendered with ordinary, focusable links and no
  `hidden`/`inert`/`aria-hidden`/conditional-rendering guard, so keyboard focus could move into
  links the user could not see while the drawer reported closed. The axe smoke tests also
  filtered results to `serious`/`critical`, so a `moderate`/`minor` violation would have passed
  silently. **Fix:**
  - `app/globals.css`: the closed drawer now also sets `visibility: hidden` (delayed on close so
    the slide-out animation still plays, immediate on open), reset back to `visibility: visible`
    unconditionally in the `min-width: 768px` desktop override. `visibility: hidden` removes an
    element and its descendants from both the tab order and the accessibility tree, which
    `getByRole` respects.
  - `bio-fnd-007-shell.spec.ts`: the three axe tests now assert `results.violations` is empty
    with no impact-level filter (a `WAIVED_RULE_IDS` list exists for any future deliberate,
    reviewed exception, currently empty); added a new test that tabs from the nav-toggle button
    and asserts focus never lands inside `.biolog-primary-nav` while it is closed, plus asserts
    the closed nav resolves to zero elements via `getByRole('navigation', { name: 'Primary' })`.
  - Re-ran the full suite after the fix: `tsc --noEmit` and `next build` clean,
    `tests/foundation/BIO-FND-007.test.sh` 25/25, vitest 12/12, Playwright 16/16 (one net-new
    test) — all captured fresh in this evidence directory, superseding the round-1 output.

## Decisions and assumptions

- **Brand colours.** No dedicated brand-guideline document exists in the repository. `#F4502A` and `#0B2341` are the only two colour values with a traceable source (the approved wordmark SVG's icon fill, and the Card Designer v0.3 spec's navy text colour respectively) and match the "orange/navy" the AC names, so they are treated as the approved palette rather than invented. Flagged in the `web/public/brand/README.md` provenance note for anyone with the actual brand guideline to correct.
- **Demo session/permission profiles are placeholders, not RBAC.** `context/session-context.tsx`'s three named profiles and permission strings (`nav:card-designer`, etc.) are invented for this story so the mechanism (AC03) is demonstrable and testable before an identity/tenant story exists. They carry no authentication and are clearly marked `SYNTHETIC`; a later identity/RBAC story is expected to replace the provider's body, not the `SessionContext` shape consumers read.
- **`governance/feature-path-ownership.json` vs. this story's actual scope.** That file's auto-generated `BIO-FND-007` entry restricts owned paths to `web/features/bio-fnd-007/**` (and equivalent `api/`/`mobile/`/`tests/`/`docs/`/`evidence/` subtrees) — the same uniform per-feature template applied to all 83 stories in the file, including the four other Wave W02 foundation/shell stories (`BIO-FND-008` api-shell, `BIO-FND-009` observability, `BIO-FND-010` traceability-tooling). Taken literally this would make it impossible to create `web/package.json` or `web/app/**` at all. The approved story, the Definition of Done, and `web/README.md` itself (committed ahead of this story: *"The application shell and design-system foundation are scaffolded by BIO-FND-007 ... This directory intentionally holds no build tooling yet so that story can create it without conflict"*) all agree the shell belongs at `web/` root — a higher-priority source per the authoritative order. Resolved in favour of the higher sources: scaffolded at `web/` root; touched nothing under this story's own `read_only_shared_contracts` list (`contracts/**`, `docs/adr/**`, `governance/**`, `scripts/check-contract-freeze.py`, `docs/architecture/SHARED-CONTRACT-FREEZE.md`). Flagged to Kemi/god for a governance fix so `BIO-FND-008` (Emeka, same conflict) doesn't hit the identical question. Not blocking since no shared/frozen contract was touched and the change is local-commit-only.
- **`scripts/quality.sh` and `tests/frontend/{package.json,vitest.config.mjs,playwright.config.mjs}`.** These are shared files already additively edited by each prior foundation story (every `BIO-ARC-*`/`BIO-FND-006` harness line was added the same way). Followed that established precedent: added one new line/devDependency/test-glob entry each, without restructuring anything already there.
- **Next.js 16's auto-generated `AGENTS.md`/`CLAUDE.md`.** `next dev`/`next build` in this version writes framework-guidance files for AI agents into the project root by default. Disabled via `agentRules: false` in `next.config.mjs` — a second, differently-scoped `CLAUDE.md` inside `web/` risked being read as project instructions by an agent working in that subdirectory in this multi-agent environment.
