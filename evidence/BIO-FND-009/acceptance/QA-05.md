## BIO-FND-009-QA-05 — High — redaction covers only one of the default log providers

`WebApplication.CreateBuilder` registers Console, Debug, and EventSource logging providers by default. `ObservabilityModule.RegisterServices` adds/configures the console provider and its `BiologJsonConsoleFormatter`, but does not remove the other providers.

Each provider receives the original `LogEntry` independently. Debug and EventSource do not call `BiologJsonConsoleFormatter.Classify`, do not understand `SafeLogValue`, and do not suppress exception messages. A classified value that the JSON console path reports as `[WITHHELD]` can therefore still be emitted verbatim through a debugger output stream or EventSource/EventPipe capture. AC04 says secrets and biometric payloads are excluded from logs by default, not only from stdout.

The reviewed documentation also says there is no separate viewer to run, which does not account for these active sinks.

Required closure: make the redaction boundary authoritative for every provider enabled by default. For the local console-only design, remove the default providers before adding the redacting console provider, and add an executable regression that resolves `IEnumerable<ILoggerProvider>` from the composed host and proves only the intended redacting provider is registered. If other sinks are required, they must enforce the same classification policy before receiving content.
