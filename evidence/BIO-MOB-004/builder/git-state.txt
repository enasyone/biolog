    feat(BIO-MOB-004): mobile card/NFC/QR/face verification flows
    
    Implements online and permitted-offline identity verification for mobile
    officers (AC01-AC05):
    
    - AC01: a sanitised VerificationDecisionResult (no biometric evidence/score
      field at all) is the only shape a decision ever travels in, both over the
      wire and in the mobile UI.
    - AC02: online requests get a live, policy-evaluated decision from this
      story's own backend; offline requests fall back to BIO-ACC-003's already-
      built AccessCacheService revocation check - a genuine reduced-capability
      path, not a new mechanism. The verify screen labels which path produced
      each result and flags a stale cache.
    - AC03 (approved by Kemi, hive thread conv-bio-mob-004-ac03, formalized as
      an extension to ADR-0006's actor-identity/authorization-boundary scope for
      the device-authenticated case): a closed VerificationDeviceRole
      (Officer/Supervisor) attached to the already-authenticated device, not a
      human actor mobile has no way to identify yet. Officer (default) may
      execute a decision and read history; only Supervisor may override a
      computed deny, always with a mandatory reason code. Role assignment is a
      real human-actor-RBAC-gated write (ADR-0006 Decision 3 + BIO-IDN-006).
    - AC04: the decision endpoint requires an Idempotency-Key header and passes
      it straight through to BIO-ACC-002's own already-reviewed idempotency
      guarantee - no duplicated store.
    - AC05: mobile/lib/features/verify/verify_screen.dart (previously a
      BIO-MOB-001 placeholder) is wired to real VerificationService/
      VerificationSyncClient calls against this story's own
      /api/v1/mobile-verification/* routes.
    
    Backend: new Biolog.Features.MobileVerification project
    (api/features/bio-mob-004/), registered via BioMob004Module. Consumes
    BIO-ACC-002's own internal AccessDecisionService in-process via a manual
    factory that substitutes a device-resolved tenant provider (never the
    reflection-based DI activator, never BIO-ACC-002's own HTTP layer or its
    actor-provenance secret) - the same architectural shape already established
    for DeviceRegistry's ICrossTenantDeviceLookup.
    
    No new canonical-id prefix minted (reuses evt_/per_, per the mobile
    canonical_id.dart contract-ownership rule).
