    BIO-DOC-001: Document Verify session and evidence foundation
    
    Provider-neutral domain model for Document Verify (api/features/bio-doc-001/
    Biolog.Features.DocumentVerify), ahead of the MRZ/barcode/OCR/NFC engines
    that will populate it:
    
    - DocumentSession (AC01): pre-person or person-linked onboarding, ADR-0001
      Decision 3 optimistic concurrency.
    - DocumentEvidence (AC02): immutable source-image evidence with SHA-256
      hash and page/side metadata.
    - DocumentFieldEvidence + BoundingBox (AC03): raw/normalized value,
      confidence, source engine, optional bounding box.
    - PersonFieldChangeProposal (AC04): a proposed PERSON field change that is
      never auto-applied - inert until Accept(actor) returns a new, separate
      record.
    - DocumentConflict + ManualReviewState (AC05): conflicting field evidence
      with a pending/in-review/resolved lifecycle.
    - InMemoryDocumentSessionStore: reference orchestration wired into the API
      host via Modules/DocumentModule.cs (no HTTP endpoints yet - no real
      tenant resolution or persistence exists anywhere in this codebase for
      them to be built against safely; see docs/features/bio-doc-001/
      DOCUMENT-VERIFY-FOUNDATION.md for the full reasoning, including why no
      new ADR-0001 identifier prefix was requested and why no migration was
      proposed).
    
    56 developer tests (tests/features/bio-doc-001/Biolog.Features.DocumentVerify.Tests)
    plus a 43-check offline structural harness (tests/foundation/BIO-DOC-001.test.sh),
    wired into scripts/quality.sh.
