# BIO-DOC-001 acceptance audit

**Decision: FAIL / CHANGES REQUIRED**

Reviewed remediation `e3e376de7449e9ff96a01ffcf7552b909c7f3233` at reviewer head `9dd5d8a`.

## QA-03 — High — evidence factory validation is optional

`DocumentEvidence`, `DocumentFieldEvidence`, and `BoundingBox` expose public `required init` properties and no private constructor. Any caller can use an object initializer instead of `Create`, bypassing all validation.

The acceptance probe constructs, through the public production API:

- a source image with empty tenant/session identifiers, sequence and page zero, `not-a-hash`, empty MIME/timestamps, and undefined enum values;
- field evidence with sequence zero, empty provenance, `NaN` confidence, undefined source/classification, and a directly initialized bounding box with negative, `NaN`, zero, and greater-than-one components.

The process reaches both print statements. The constructors do not throw. This contradicts the implementation's own claim that invalid evidence is unrepresentable and weakens AC02/AC03 evidence integrity. The records are immutable after construction, but immutability preserves invalid content rather than validating it.

### Reproduction

```sh
dotnet run --project evidence/BIO-DOC-001/acceptance/InvalidEvidenceProbe/InvalidEvidenceProbe.csproj
```

The probe prints both invalid objects and deliberately exits `1` while the bypass exists.

Required closure: make validated construction mandatory. Use non-public constructors/properties or another boundary that prevents direct invalid initialization, preserve serializer/persistence needs explicitly, and add adversarial compilation/runtime tests proving callers cannot create invalid image, field, or bounding-box records without passing the factory invariants.
