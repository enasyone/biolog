# BIO-OPS-005 Security Review — Zainab

**Frozen builder:** `6bf77b0b7e8ba5457e01a8cb5fe1c626134faff3`  
**Verdict:** PASS

## Threat-model results

- **Tenant isolation:** PASS. The coordinator resolves the tenant from the
  verified ambient tenant context. The session identifier is generated by the
  server, carried only in a `Secure`, `HttpOnly`, `SameSite=Strict` cookie, and
  every store operation resolves the tuple `(ambient tenant, session id)` with
  not-found equivalence for a foreign tenant.
- **Authorization / actor substitution:** PASS for this surface under ADR-0006
  Decision 1. Every kiosk workflow operation is uniformly available; the asserted
  actor changes audit attribution only and grants no differential authority.
  Consequential authenticity override/read endpoints remain unmapped. The session
  cookie, not `X-Actor-Id`, selects the mutable aggregate.
- **Sensitive document and biometric data:** PASS. HTTP responses contain state,
  summary, confidence, and sequence-number provenance, not raw MRZ, optical
  character recognition, barcode, or PERSON values. Barcode storage retains only
  the payload hash. The selfie step is explicitly synthetic and collects no real
  biometric data.
- **NFC truthfulness:** PASS. No chip transport is constructed, no NFC evidence is
  appended, and the response is `not-checked` with `unavailable` provenance and
  zero confidence.
- **PERSON integrity / manual review:** PASS. Engine output can only append
  evidence and immutable `PersonFieldChangeProposal` records after a person is
  linked. No coordinator route applies a proposal or rewrites raw evidence.
  Genuine mismatches raise evidence-linked conflicts and enter manual review.
- **Replay / concurrency:** PASS. Replaying a read appends new evidence rather than
  overwriting prior records. Authenticity checks are serialized per unguessable
  document session before caller-side comparison-version allocation; the
  underlying two-phase version store preserves audit-before-commit behavior.
- **Cross-source provenance:** PASS. MRZ, barcode, and optical character
  recognition results carry their actual engine source and stored evidence
  sequence numbers. Identification is derived from stored optical character
  recognition evidence. NFC and deliberately simulated steps are labelled
  honestly.
- **Secrets / logging:** PASS. The change adds no secret, token logging, raw
  document logging, or caller-controlled tenant field.
